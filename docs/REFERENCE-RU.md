# BuildKit

Paper-плагин для headless-построек: структуры с поворотом/отражением, пакетные скрипты,
сетка, проверка проходимости, снимки и откат. Всё управление — одной консольной командой `/bk`,
без Gradle, WorldEdit и `//`-команд.

- Сервер: Paper 26.1.2 (проверено на `26.1.2-74-e4e17fc`, Java 25).
- Сборка: `bash build.sh` (ECJ + упаковка jar на Python, Gradle/Maven не нужны).
- Исходники: `src/main/java/com/nous/buildkit/`.
- Данные в рантайме:
  - `plugins/BuildKit/structures/<имя>.bk` — библиотека структур;
  - `plugins/BuildKit/snapshots/` — автоснимки (`auto-*.bk`) + именные снимки + `index.tsv`;
  - `plugins/BuildKit/scripts/` — скрипты для `/bk run` и экспорт `.bk` → setblock-файл.

## Команды

```
/bk save <имя> <x1 y1 z1> <x2 y2 z2>           снять область в structures/<имя>.bk
/bk place <имя> <x y z> [rot=0|90|180|270] [mirror=none|x|z]
                                              вставка; (x y z) — min-corner результата
/bk list                                      библиотека структур
/bk info <имя>                                размеры, объём, палитра, число блоков
/bk grid <имена> <x y z> <dx dz> <nx nz> [cycle|seeded]
                                              сетка nx×nz с чередованием вариантов
/bk run <файл> [--tick-budget=N]              скрипт из scripts/, N блоков на тик (по умолчанию 20000)
/bk walkcheck <x1 z1> <x2 z2> [y]             проходимость по колонкам (BFS)
/bk probe <x y z>                             столбец: RLE сверху вниз
/bk box <x1 y1 z1> <x2 y2 z2>                 послойный дамп с RLE по палитре (до 200 строк)
/bk snapshot <имя> <x1 y1 z1> <x2 y2 z2>      именной снимок в snapshots/
/bk undo [n]                                  откат последних n операций по автоснимкам
/bk export <имя> <x y z> <файл> [rot=..] [mirror=..]
                                              .bk → scripts/<файл> из setblock-команд
```

Флаг `--force` (для `place`/`grid`/`run`) обходит проверку чужих регионов; каждый такой случай
пишется в лог с именем оператора и bbox.

### Права

`buildkit.use` — базовый доступ (default: op), плюс отдельные ноды `buildkit.place`, `buildkit.run`,
`buildkit.undo` (тоже op). Без `buildkit.use` команда отклоняется, в лог пишется отказ.

## Геометрия поворотов — важно

- Точка привязки `place` и `grid` — **min-corner** (минимальный угол bbox результата), не центр.
- `rot` — поворот **по часовой стрелке, если смотреть сверху**: `rot=90` переводит
  север → восток, восток → юг, юг → запад, запад → север.
- `rot=90/270` меняет местами размеры по X и Z (10×10×10 остаётся 10×10×10, 5×4×6 при 90° станет 6×4×5).
- `mirror=x` — отражение по оси X (`x → -x`, восток ↔ запад), `mirror=z` — по оси Z
  (`z → -z`, север ↔ юг). В терминах ванильных структур: `x` = `front_back`, `z` = `left_right`.
- Порядок применения: **сначала отражение, потом поворот** (как в ванильном `StructureTemplate`).
- Состояния блоков трансформируются ванильной логикой (`BlockData.mirror/rotate`): `facing`, `axis`,
  `half`, `shape` (лестницы/рельсы), `hinge`, `open`, `rotation` (знаки/баннеры), соединения
  стен/заборов/стёкол/труб, `type` плит и т.д. Ручных таблиц для отдельных блоков нет —
  используется серверная реализация, поэтому поведение совпадает со structure block.

## Формат `.bk`

Бинарный, gzip, версия 1 (см. `BkIO.java`):

```
int   magic "BKS1"
byte  version = 1
byte  type: 1 = структура, 2 = changeset (снимок "до")
UTF   label, UTF world, long createdAt
int   sx, sy, sz
int   paletteSize; UTF[paletteSize]        // полные blockstates, напр. minecraft:oak_stairs[facing=...]
type 1: int count = sx*sy*sz; int[count]   // индекс в палитру, порядок y → z → x
type 2: int count; {int x, int y, int z, short paletteIndex}[count]; boolean truncated
```

Порядок индексов: `index = ((y * sz) + z) * sx + x`, где x/y/z — локальные координаты от min-corner.

## Скрипты `/bk run`

Построчно, `#` — комментарий, пустые строки пропускаются:

```
# пример
fill 2000 99 2000 2010 99 2010 minecraft:stone
setblock 2005 100 2005 minecraft:oak_stairs[facing=east,half=top,shape=straight]
fill 2000 100 2000 2010 102 2010 minecraft:air replace
place houseA 2020 100 2000 rot=90 mirror=z
wait 20
```

- `setblock <x y z> <block[states]> [replace|keep|destroy]`
- `fill <x1 y1 z1> <x2 y2 z2> <block[states]> [replace|keep|destroy]`
  (`keep` — только воздух/заменяемые блоки, `destroy` — всё, но **без дропа предметов**)
- `place <имя> <x y z> [rot] [mirror]`
- `wait <тики>`

Скрипт разбирается и валидируется **целиком до первого блока**: неизвестная команда, кривой
blockstate, отсутствующая структура — отказ с номером строки и текстом строки. Выполнение идёт
порциями по тикам, консоль не блокируется; в лог пишется `выполнено K/L команд`, при ошибке —
строка и текст.

## Лимиты и безопасность

- Максимальный объём одной операции (`place`, `grid`, `run`, `undo`) — **200 000 блоков**;
  отказ с указанием, сколько просили. Свыше 50 000 — предупреждение.
- Максимальный размер структуры (`save`, `snapshot`) — **64 × 256 × 64**.
- `box` — до 64 000 блоков и 200 строк, `walkcheck` — до 400 000 клеток поиска (синхронно).
- Весь доступ к миру — в main thread, порциями по тикам. По завершении в лог пишется
  `TPS min` за операцию.
- Перед `place`/`grid`/`run` проверяются регионы WorldGuard и клаймы GriefPrevention по bbox.
  Если регион чужой (для игрока — он не owner/member; для консоли — любой регион) операция
  прерывается **до первого блока**. Ошибка самой проверки — тоже отказ (не «молча продолжаем»).
  Осознанный обход — `--force`, всегда с записью в лог.
- Перед каждой операцией пишется автоснимок `snapshots/auto-*.bk` (только реально изменённые блоки),
  `/bk undo` возвращает блоки и blockstates. Автоснимок пишется и при ошибке в середине операции.
- CoreProtect не отключается: массовые правки попадают в его лог (команды предупреждают об этом).
- При загрузке плагин не трогает мир: только создаёт каталоги и регистрирует команду.

## Ограничения (осознанные)

- Сохраняются **blockstates**, но не содержимое block entity: текст на табличках, инвентари
  сундуков/бочек, команды в командных блоках, узоры баннеров, содержимое рамок. Сами блоки и их
  состояния (включая `rotation` баннеров/знаков) переносятся.
- `destroy` в `fill` не спавнит дроп (в консоли это чаще вредно, чем полезно).
- Структуры и снимки не переносят сущности (животные, стойки, вагонетки).
- `undo` работает по автоснимкам; именной `/bk snapshot` — это файл-снимок для сверки/ручного
  восстановления, в очередь undo он не попадает. Если снимок обрезан по лимиту 600 000 блоков,
  откат этого шага пропускается с предупреждением (честно, а не «частично»).
- Границы мира зашиты как Y −64..319 (в API 26.1.2 у `World` больше нет min/max height).
- `/bk save` и `/bk snapshot` тоже идут задачей по тикам: файл появляется после `готово` в логе.

## Приёмка

Все 6 критериев прогнаны на локальном `/home/fedor/mc-test` (Paper 26.1.2-74-e4e17fc, Java 25),
живой сервер до зелёных тестов не трогался. Логи прогона: `/home/fedor/.hermes/cache/scratch/bk/accept.log`
(основной) и `edges.log` (пограничные случаи); скрипты прогона — в том же каталоге.

- `save` 10×10×10 → `place` → послойная сверка: 1000 блоков, 0 отличий по blockstates
  (лестницы shape/half/facing, двери hinge/open, люки, рельсы, знаки/баннеры rotation, стены/заборы/панели).
- `rot=90/180/270` и `mirror=x/z`: по 1000 блоков, 0 отличий от независимой реализации правил
  (позиции + facing/axis/rotation/shape/hinge/соединения); `dir` rot=90 сверен с РУЧНОЙ копией — 0 отличий.
- `run` 5000 команд: 0.2 с, `выполнено 5000/5000`, TPS 20.00.
- `walkcheck`: переулок 3 блока — «проходимо: да», 50 шагов, сужение 1 блок в (2202,2050);
  коридор с забором — «проходимо: нет», упор в (2212,100,2030).
- `snapshot` → `place` → `undo` → сверка: 1000 блоков, 0 отличий.
- Запуск: `[BuildKit] Enabled`, ошибок нет, `/bk` даёт help, не-op получает отказ.

## Известные ограничения

- `undo` не проверяет регионы (восстанавливает прежнее состояние) — это осознанно.
- Автоснимок пишется на диск по завершении операции (в памяти прежние состояния фиксируются
  до каждой установки блока); при жёстком падении сервера посреди операции этот шаг не откатить.
- Очередь операций одна: одновременно выполняется только одна задача.
